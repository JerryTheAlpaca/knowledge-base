# 10 · 网页版 UI 重构方案（第一性原理信息架构重设计）

> 状态：**已实施（2026-09-09，P0+P1+P2 全量落地）**，实施记录见 §9。仅前端改造：`web_static/inbox.html`、`tokens.css`、`authorize.html`（顺带对齐）。**不改任何 API、不改数据流、不删功能**——所有现有效能（采集/列表/详情三页签/设置/登录/B 站登录态/草稿保护/增量轮询）全部保留，只改变其组织方式与呈现层级。

## 1. 目标与原则

从第一性原理出发，这个网页只服务四个用户任务：

1. **丢进来**：粘贴链接/文字/文件，交给服务器。
2. **看进展**：条目处于提取、加工、发布的哪一段，卡住了怎么办。
3. **读结果**：看提炼、翻原文、导出成品。
4. **配一次**：模型 Key、B 站登录态，配完很少回来。

由此推出三条重构原则：

- **P1 用户语言替代系统语言**：界面上出现的每一个字都应回答用户的问题，而不是复述数据库。版本号（`r3 · bundle r2`）、cid/bvid、凭据版本、adapter 类型等属于日志和排障，默认不出现在界面上。
- **P2 一卡一主题**：每张卡片只回答一个问题。混排即拆卡。
- **P3 低频即折叠**：配置类、技术类、危险类区域默认折叠，展开即得，不占首屏。

## 3. 新信息架构总览

```
知识收件箱
├── 收件箱（默认 Tab）
│   ├── 采集卡        回答：丢什么进来
│   │   └── 更多选项（折叠：备注、附件）
│   ├── 条目列表卡    回答：进展如何
│   └── 详情（二级视图，?item= 直达）
│       ├── 头部：返回 / 标题 / 状态 badge / stepper
│       ├── 主操作条（随状态唯一主按钮）
│       ├── 页签一 · 提炼   回答：AI 整理出了什么（ready 时默认）
│       ├── 页签二 · 原文   回答：实际取到了什么
│       └── 页签三 · 管理   回答：我能对它做什么
│           ├── 操作区（重新加工 / 重新提取 / 下载清单）
│           ├── 补充材料（折叠，needs_input 时自动展开）
│           ├── 导出文件（折叠，点击「导出」自动展开）
│           ├── 技术细节（折叠：版本 / 定位 / 保留期 / item_id）
│           └── 危险区（折叠：删除服务器材料）
└── 设置（Tab，原「模型与账号」）
    ├── 账号卡       回答：我是谁（用户名 / 登录方式 / 管理员入口）
    ├── 模型卡       回答：用哪个大语言模型（默认配置 + LLM 配置列表 + 新建）
    ├── 平台接入卡   回答：B 站登录态是否正常（状态 + 更新/检测/撤销，元信息折叠）
    └── 高级（折叠） vision_ocr 配置管理（有则列出，无则不显示该折叠区）
```

### 3.1 关键结构决定

- **设置页无侧栏**：四张卡纵向排列，总高约一屏半，直接滚动。删除 `settings-grid`、`anchor`、`spySettings` 及 scroll 监听。
- **模型卡只含 LLM**：`renderProfileCards` 过滤 `kind === "llm"`；新建配置固定 `kind: "llm"`（`adapter: "openai-compatible"` 不变）。vision_ocr 存量配置不删数据，移入「高级」折叠区只读管理（测试/换 Key/撤销沿用现有接口）。
- **B 站归入「平台接入」**：它与「内容从哪来」同主题，与模型无关。卡片结构不变（状态卡 + SESSDATA 输入 + 三按钮），仅把凭据版本/更新时间/最近检测折叠。
- **详情三页签定序「提炼 / 原文 / 管理」**：默认页签 = `ready` 时「提炼」，否则「原文」。`detailTab` 初值逻辑相应调整；`jumpToSegment` 内部切到「原文」逻辑不变。
- **「技术细节」统一折叠组件**（`<details>` 或同款 disclosure）：集中收纳 S1/S3/S4/S5 的版本号、定位、保留期、item_id，一处定义全站复用。
- **主操作条唯一主按钮**逻辑沿用现有（failed→重试 / needs_input→去补充 / ready→导出），移到 stepper 正下方、页签之上，不再埋在「管理」页签里。

## 5. 视觉设计（tokens.css v2）

### 5.1 色板

保留暖纸底 + 陶土橙基调，微调：

- `--border` 略加深（#E5E2D8），卡片在暖纸底上更可辨；
- `--accent-soft` 深色模式由 #3B2F27 调浅一档，保证 badge 文字对比 ≥4.5:1；
- 新增 `--surface-2`（嵌套卡/折叠区底，light=#F5F3EC / dark=#242320），替代目前 `var(--bg)` 充当嵌套底造成的「底卡同色」。

### 5.2 字阶（显式化）

| 层级 | 规格 | 用途 |
|------|------|------|
| Display | 22px / serif / 600 | 品牌、空状态标题 |
| H1 | 20px / 600 | 详情标题 |
| H2 | 16px / 600 | 卡片标题 |
| Body | 15px / 1.6 | 正文、列表标题 |
| Small | 13px | 辅助说明、aux 行 |
| Caption | 12px | 时间、版本、证据编号 |

正文与 UI 一律 sans；serif 仅限 Display（现状即如此，固化为规则）。

### 5.3 圆角与间距

- 圆角层级：`--radius-card:16px`（页面卡）/ `--radius-inner:12px`（嵌套卡、列表行、折叠区）/ `--radius-ctl:10px`（按钮、输入）/ pill 不变。
- 间距以 4 为基：4/8/12/16/24/32；卡片 padding 桌面 24、移动 16；卡片间距 20。

### 5.4 层次与形状

- 页面卡：1px border + `--shadow-card`；hover（仅可点卡/列表行）加 `--shadow-pop` + `translateY(-1px)`，reduced-motion 下只换阴影。
- badge/chip/pchip 统一为 pill 组件三种尺寸（badge 12px 文字 / chip 12px / pchip 可点 30px 高），删各自为政的边框规则。
- 折叠组件（disclosure）：`--surface-2` 底 + 12px 圆角 + ▸ 旋转指示，全站唯一实现。

### 5.5 深色模式走查

- 逐 token 校验 badge 四色（ok/warn/bad/info）深浅两套对比度；
- Toast/Modal 阴影在深色下加深；
- stepper 的 `sball` 空心圆在深色下边框用 `--border-strong`。

### 5.6 authorize.html

仅同步 tokens v2 与按钮/卡片圆角，不改结构与流程。
