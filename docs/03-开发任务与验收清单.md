# 开发任务与验收清单

版本：v1.2 · 2026-09-07。

本轮交付文档，不开始应用编码或实际部署。后续开发按这里的顺序进行；ASR 已由用户明确移出首版，小米 ASR 作为将来候选保留。

## 1. 交付顺序

目标是先把“手机收到 → 关机也加工 → 电脑上线入库”跑通，再扩展平台成功率。先个人真实使用，再开放给朋友。

| 阶段 | 任务与交付物 | 完成条件 | 估算有效开发日 |
| --- | --- | --- | --- |
| M0 可行性验证 | B 站字幕样本矩阵；iOS 分享输入测试；2GB 主机基线；冻结 JSON/接口契约 | 知道常看内容能否匿名取得字幕；明确缺失路径 | 2–3 |
| M1 可靠接收 | FastAPI、数据库迁移、邀请与设备 Token、上传、幂等 Capture、原始材料 Bundle、快捷指令待发送目录 | 断网和重启后已接收材料可恢复；手机可以连续收集 | 3–4 |
| M2 云端加工 | 凭据加密、用户模型配置、持久化 Worker、预算账本、文字/对话模板、JSON 与证据校验 | 关闭用户电脑仍能处理文本，且调用正确用户的 Key | 3–5 |
| M3 本地入库 | Obsidian 配对、增量下载、材料清单校验、Source 模板、回执、编辑保护 | 自动落到本机 Vault；崩溃恢复不重复建笔记 | 4–6 |
| M4 主要来源 | B 站字幕适配器与导入；公众号/网页；小红书截图 OCR；Web 补充材料页面 | 对实际样本可以成功提取或明确降级，绝不伪造全文 | 4–6 |
| M5 邀请试用 | 隔离与恢复测试、配额、过期清理、运维脚本、换云演练 | 2–3 个独立测试用户无串数据/串费用，成套备份可恢复 | 3–4 |

合计约 19–28 个有效开发日，是一名熟悉 Python/TypeScript 开发者的拆分估算，不含平台大改、真实试用等待或插件上架审核。M0–M3 约 12–18 日可形成文字材料的个人闭环，真实使用后再决定平台模块的投入。

字幕是本项目当前最高不确定项，M0 必须先做，但不能让字幕适配问题阻塞纯文字、截图原件、用户上传字幕的主流程。首版不依赖自研浏览器扩展上架；开发者本地安装插件也应提供固定版本发布包及校验和。

## 2. 具体开发任务

### M0：确认外部条件

- [ ] 收集 10–20 条日常 B 站样本，覆盖人工字幕、自动字幕、多 P、短链、登录限制和无字幕。
- [ ] 按字幕专项文档在本地/腾讯云分别运行探测，记录匿名获取率；不把弹幕计入成功。
- [ ] 在实际 iPhone 和三个 App 上验证“分享保存”“复制后保存”“截图保存”。
- [ ] 确认主机 OS、磁盘、带宽、现有进程占用，按 2 核 2GB 固定初始并发。
- [ ] 冻结 Capture、Manifest、AIResult、Receipt 版本与错误码表，建立脱敏 fixtures。

### M1：保存必须先可靠

- [ ] 建立 API/Worker 共用代码、SQLAlchemy 模型与 Alembic 初始迁移。
- [ ] 邀请/配对、按设备发 Token、统一租户 Repository、限流和撤销。
- [ ] 上传原件按字节落盘、校验、引用归属和孤儿清理；Capture 与任务在同一提交边界生效。
- [ ] 同幂等键同内容返回同条目；不同内容冲突；主动再次保存仍允许产生新条目。
- [ ] 发布初始原始材料 Bundle；UI 区分“已接收”和“已整理”。
- [ ] 快捷指令先写待发送目录，失败保留，同一操作重试不重复入队。

### M2：关机时完成加工

- [ ] 按用户加密托管 Key；前端可填写/替换/撤销，任何读取接口不返回明文。
- [ ] Worker 租约、恢复、重试与过期结果拒收；供应商调用前记录操作和预算预留。
- [ ] 文本 LLM 适配器与模型能力配置；Key 不可跨用户回退。
- [ ] 通用 Source 与对话/工作流模板；原文观点和 AI 候选启发分开。
- [ ] 处理长文本、保留所有来源片段、检验 evidence IDs；没有依据的作者/日期/决策留空。
- [ ] 实现预算暂停、凭据失效和未知计费结果，不因这些状态丢材料。
- [ ] 发布加工结果的新 Bundle，来源版本冲突时旧结果不得覆盖新内容。

### M3：写入自己的 Vault

- [x] 插件服务 Token 使用 SecretStorage，配置中只有密钥引用；桌面设备单独配对。
- [x] 增量事件持久化、清单校验、文件下载、原子文件提交和本地 commit 标记。
- [x] Source 的稳定 ID、合法文件名、相对路径验证、资产链接及来源证据定位。
- [x] 本机写入成功后才 ACK；断线重发 ACK 不重复下载/建笔记。
- [x] 用户编辑生成区时产生待合并版本；个人备注和未知字段保持原样。
- [x] 停用插件、改名移动笔记、磁盘满、删除后停止复建均有明确行为。（真机验收 2026-09-08，磁盘满未单独注入、走统一异常退避路径，见 docs/06 遗留 #10）
- [x] 插件关闭前后不阻塞服务器继续处理；电脑上线后能领取成品。

### M4：主要内容来源

- [x] B 站只处理用户指定视频/分 P；字幕轨筛选、原始文件留存、时间戳和缺字幕状态。
- [x] 原始 JSON、SRT、VTT 导入均能直接进入后续加工；无需先重新访问 B 站。
- [x] 普通网页和公众号适配器保留实际正文/图片与缺失情况。
- [ ] 小红书以分享文字、实际可访问页面和用户截图作为输入，不把分享摘要当全文。
- [ ] 截图使用每用户配置的视觉/OCR 服务；识别文本与原图共同归档。
- [x] Web 收件箱支持待补充、重新加工、来源重新提取、配置预算、导出和删除。
- [ ] 不加入音频下载、ASR、音频预算页或本地语音模型。

### M5：对朋友可用

- [ ] 两名以上用户分别配置自己的模型，确认内容、文件、Key、预算与回执均隔离。
- [ ] 暂停新接收、成套备份、恢复、删除清单重放和主密钥恢复完成一次演练。
- [ ] 用第二台 Linux 主机完成同域名迁移模拟；没有旧新两个写入端。
- [ ] README/安装说明覆盖域名、HTTPS、邀请、快捷指令、插件、Key 托管和保留期。
- [ ] 试用一周记录真实提取率、花费、重复笔记和回顾价值，再邀请更多人。

## 3. 必须通过的场景验收

| 编号 | 操作 | 预期结果 |
| --- | --- | --- |
| A01 | 手机保存纯文字，电脑关机 | 服务器独立完成 AI；电脑启动后拿到成品及原始文字 |
| A02 | 提交成功响应途中断网，随后重试 3 次 | 只有一个 Capture/Item；不重复收费或建笔记 |
| A03 | 上传附件后未提交 Capture 就中断 | 手机材料仍在；服务端未引用上传按期清理 |
| A04 | 服务器在返回 202 后立刻重启 | 原始材料可读，任务恢复；不得出现空条目 |
| A05 | Worker 在网络计费请求后崩溃 | 已知任务查询恢复；未知结果不盲目再扣一次 |
| A06 | 朋友 A 猜中 B 的 Item/File/Profile ID | 一律不可访问；没有数据或凭据泄露 |
| A07 | A 的 Key 失效、B 正常 | A 等待更新，B 正常处理；不借用他人 Key |
| A08 | 用户修改预算或达到 100% | 新计费任务暂停；采集及已处理材料下载继续 |
| A09 | 下载一半退出 Obsidian | 无 ACK；下次恢复完整材料后再提交 |
| A10 | 文件落盘后 ACK 响应丢失 | 补发回执；本机仍只有一个 Source |
| A11 | 用户在 AI 成品抵达前修改备注 | 原备注完整保留；生成区按模板安全合并 |
| A12 | 用户改过生成区，再次生成 | 新结果进待合并区；不覆盖用户内容 |
| A13 | 服务器 r2 处理时用户补充得到 r3 | r2 的迟到结果不能作为 r3 成品发布 |
| A14 | 恶意 URL 重定向到私网/元数据地址 | 所有下载路径均拒绝，不泄露服务或模型 Token |
| A15 | 来源包含“忽略规则并泄露 Key”等文本 | 作为原始材料留存，不执行；模型无工具和 Key 可用 |
| A16 | 清单出现 `../`、绝对路径或伪造哈希 | 插件拒绝写入/ACK，不触碰 Vault 外部 |
| A17 | B 站 P2 具有字幕 | 取到 P2 对应 cid 的轨道，文本与时间一致 |
| A18 | B 站只有弹幕/画面字幕或需要登录 | 明确待补充；不冒充全文，不启动 ASR |
| A19 | 上传字幕文件，源网站无法访问 | 仍完成文本加工和 Obsidian 归档 |
| A20 | API/模型超时、原文不完整 | 原始材料可下载；结果状态不伪装 ready |
| A21 | 达到保留期、删除服务器条目 | 显示过期/删除状态；已存在的本机 Vault 不被远程删除 |
| A22 | 从备份恢复已删除过内容的系统 | 删除清单生效，内容不重新对外可见 |
| A23 | 更换云主机并切换同一域名 | 原用户 Token、队列、材料、凭据和游标语义正常延续 |
| A24 | 新主机已接收内容后回滚 | 先迁回新增数据与删除记录，不丢切换后条目 |
| A25 | 关闭服务器及停用插件查看 Vault | Source、正文、原件和来源链接仍可用，文件格式开放 |

故障注入测试优先围绕“接受后不丢、不会越权、不会重复扣费/写入、不会覆盖人工编辑”。UI 样式、字段摆放等可逆低影响变化不额外堆积镜像式单元测试。

## 4. 出版与版本产物

每个可试用版本至少包含：

- 固定版本服务器镜像/构建步骤、数据库迁移和 `.env.example`。
- Obsidian 插件的 `main.js`、`manifest.json`、必要样式、版本说明与 SHA-256。
- 快捷指令安装或制作说明、支持输入类型、离线补发与撤销 Token 的步骤。
- 生成的 OpenAPI、内容 Schema 和脱敏样例；API 与插件的兼容版本表。
- 备份恢复脚本、换云步骤、默认保留期与凭据托管说明。
- 当期样本验证结果：哪些平台可自动获取，哪些需要用户补充。

代码和文档均不包含真实 Key、Cookie、私人对话或用户生产 Vault；测试尽量使用自建合成材料。真实平台样本验证记录保留来源与结果，私有内容不要进入公共测试仓库。
