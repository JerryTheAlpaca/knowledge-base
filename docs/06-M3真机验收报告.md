## 发现并修复的 bug（真机验收价值所在）

插件侧五项 + 服务端一项（第一轮），插件侧两项 + 工具一项（第二轮），均为真机/故障注入跑通才发现的问题：

1. **user_note 读取层级错误**（engine.ts）：capture.json 结构为 `{capture: {..., user_note}}`，插件读顶层字段永远拿到 null →「我的备注」显示（无）。修复为读 `capture.user_note`。
2. **processNote 传 string 路径崩溃**（vaultfs.ts）：Obsidian `vault.process` 内部把 string 当 TFile 用（`file.saving = true`）抛 `Cannot create property 'saving' on string`，**所有"更新已有笔记"路径必然失败**（新建不受影响）。修复为先解析 TFile 再调用，拿不到走 read+write 兜底。
3. **冲突误判**（engine.ts/template.ts）：`generated_digest` 是 SHA-256，比对时却拿原文比哈希——恒不相等，**每次版本更新都被误判为冲突**进 conflicts/。修复为 pre-read 算哈希 + 回调内同步比对。
4. **双 frontmatter**（template.ts）：`mergeKbFrontmatter` 拼接时丢失结尾 `---`，下次更新识别不到完整 frontmatter 又包一层，双 frontmatter 层层叠加。修复 + smoke 补断言（原断言只查 endsWith 未查结尾 `---`，拦不住）。
5. **启动补发顺序**（main.ts）：`recoverReceipts()` 在 `refreshToken()` 之前执行，tokenCache 为 null 时补发静默 return 0——**启动回执补发是死代码**。修复为先刷新 Token 再补发。
6. **服务端 enrich 丢附件**（enrich.py `_base_bundle_files`）：按 relative_path 白名单只挑 3 个基础文件，`original_submission` role 的上传附件被过滤——**用户上传的原始材料永远不进 bundle**。修复为按 role（original_submission + source_material）筛选。服务端测试 70/70 通过后部署。
7. **恢复命令语义缺口**（第一轮遗留 #7 → 第二轮修复）：`unsuppressAll` 只清 suppression.json，本地 commit 仍在——下一个新版本事件走到 `latest && !exists(note_path)` 分支**立即再次抑制**，恢复命令永远无法触发重建（实测 15:51 suppress → 15:53 清空 → 16:03 r5 重新 suppress）。修复：恢复命令现在同步删除对应条目的本地 commit（`CommitStore.removeForItem`）并重建收件箱索引，下次事件走全新建路径。闭环验证：删笔记 → r2 触发抑制（无回执）→ 恢复命令（清 1 条 suppression + 1 个 commit）→ r3 到达 → 笔记重建 + 服务器恰 1 条 r3 回执。
8. **GONE 无限退避**（engine.ts）：服务器删除条目返回 410/GONE 后，原实现按普通错误退避重试（上限 10 分钟一次）**永不放弃**，待办队列被死条目永久占用。修复：GONE 时放弃待办、记 suppression（原因"条目已在服务器删除或过期"）、保留本地已有内容。
9. **obsidian-stub arrayBuffer 语义错误**（scripts/obsidian-stub.ts，仅影响无头工具不影响真机插件）：真机 `requestUrl().arrayBuffer` 是**属性**，stub 实现成了方法——api.ts 直接 `return res.arrayBuffer` 拿到函数对象，无头下载全部变成空文件。这也是第一轮无头驱动不可用、只能真机验证的原因。修复为属性语义后无头驱动与真机行为一致，第二轮全部场景可自动化注入。
10. **状态不可见**（main.ts/engine.ts）：被抑制/放弃条目数此前无任何 UI 呈现。状态视图新增"已放弃条目"行，`EngineStatus` 增加 `suppressedCount`。

第一轮提交：06afaaa（六项修复 + smoke 断言），已部署生产（health/ready 全绿）。第二轮修复见插件 0.1.1（main.js + manifest.json 已部署 kb-test-vault），smoke 断言扩至 12 项全过。

## 遗留问题

7. ~~恢复命令语义缺口~~ **已闭环**（第二轮修复并验证，见 bug #7 条目与场景表"恢复重建"行）。
8. **Obsidian GPU 进程间歇崩溃**（环境问题，非插件）：命令行启动反复失败（`GPU process isn't usable`），手动打开偶发闪退，但存活的实例完整跑通了同步。未影响验收结论；若持续可考虑更新显卡驱动或 Obsidian 安装器（当前 1.13.7）。第二轮因 GPU 不稳定改用无头驱动完成故障注入，真机仅做离线文件级检查。
9. **staging 空目录残留**（低优先级）：Obsidian `adapter.list` 只返回文件不返回空目录，staging 清理后遗留 `.staging-*` 空壳（下一次下载同条目时会复用/清理，无正确性影响）。headless 复刻时同样复现。
10. **磁盘满未单独注入**：制造真实磁盘满场景对开发机影响面大，未实测。落盘失败由 `processPending` 统一异常退避处理（不回执、不建笔记、保留待办），与 A09 强杀恢复共用异常路径；风险低，留待真实使用中观察。
