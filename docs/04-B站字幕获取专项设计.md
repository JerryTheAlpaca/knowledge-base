# B 站字幕获取专项设计

版本：v1.2 · 2026-09-07 · 首版范围：已有字幕获取，不做 ASR。

本文将“视频已有字幕”落实为可以验证的输入条件、提取步骤和错误处理。本次核对了公开源码与文档，未拿用户实际收藏的视频在腾讯云服务器上实测，不能把下述方案描述成已验证成功率。
> **2026-09-08 匿名实测补充**：view 接口行为不变（轨道匿名可见、`subtitle_url` 为空，
> 轨字段名为 `lan`）；player/v2 匿名响应新增明确信号 `need_login_subtitle: true`
> 且 `subtitles` 为空——普通路径仍可用，无需切换 WBI。实现（1.1.0）按
> need_login_subtitle → 有轨无 URL → view 辅助（多 P 只作参考）的顺序判定，
> 新增 `unconfirmed`（证据不足不妄称无字幕）与 `POST /v1/bilibili-session/test`
> 登录态检测；SESSDATA 只发 api.bilibili.com，字幕 CDN 不带 Cookie。
> 详见 [docs/07](07-本轮改造实施与验收记录.md)。带真实登录态的端到端样本仍未实测。


## 1. 先明确拿哪一种字幕

| 用户看到的内容 | 能否作为文本轨尝试获取 | 首版处理 |
| --- | --- | --- |
| 播放器里可开关的 CC/字幕轨 | 可以探测，但可能受登录和访问状态限制 | 主路径 |
| 平台提供的自动字幕 | 有独立可访问轨道时可以 | 标注自动字幕，保留原始文本及时间 |
| 直接压在画面里的文字 | 不一定存在独立字幕文件 | 保留链接待补文字；首版不逐帧 OCR 或 ASR |
| 弹幕 | 属于观众评论，不是说话内容 | 排除，不进入视频正文 |
| 视频简介、AI 看点/概括 | 可以作为独立辅助材料，不是完整字幕 | 单独记录，不伪装为视频全文 |

“大部分常看视频有字幕”应进一步测成“在当前访问方式下，大部分有可取得的独立字幕轨”。这是本模块的第一项验证任务。

## 2. 已核对的实现依据

yt-dlp 官方仓库当前 B 站提取代码包含以下行为：使用视频标识和 `cid` 请求播放器字幕信息，读取字幕轨地址，再把原始字幕的 `body` 转成 SRT；代码同时处理 `need_login_subtitle`，并在字幕结果中加入名为 `danmaku` 的弹幕项。因此登录要求、弹幕排除和原始文件保留都要单独实现。该源码是社区工具的实现依据，不是 B 站保证稳定的开放 API 合同。[yt-dlp B 站源码](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/bilibili.py)

yt-dlp 文档提供 `--list-subs`、`--skip-download`、`--write-subs`、`--write-auto-subs` 等参数，可用于技术验证。但“列出字幕”不一定只发一次字幕请求，也可能需要先完成页面/视频信息提取。[yt-dlp 使用文档](https://github.com/yt-dlp/yt-dlp)

实现必须锁定经过验证的 yt-dlp 版本或源码 commit，并把实际版本写入测试记录。不自动追随 master；本文核对的是 2026-09-07 可见源码，平台和工具以后可能改变。

## 3. 推荐实现分层

```text
BilibiliSubtitleExtractor
  resolve_share_url       展开 b23.tv 等短链
  resolve_video_part      明确 BV、当前分 P、cid、视频时长
  discover_tracks         探测字幕轨和登录要求
  choose_track            按配置选轨，排除弹幕
  download_track          下载原始字幕文件，立即落盘
  normalize_subtitles     生成统一片段及 SRT/文字稿
  publish_source          发布 source_revision 和 Bundle
```

首版可使用两种底层实现，但领域层只依赖上面的窄接口：

- **技术探测阶段使用 yt-dlp**，快速判断目标视频和服务器环境是否可行。
- **生产模块优先使用只处理元数据和字幕的 HTTP 适配器**，把网络统一接入项目受限下载器；避免因为下载视频格式失败而连字幕也无法发布。实现依据由已验证工具行为和真实样本确定。

如果使用 yt-dlp 作为生产后端，必须限定 extractor、固定输出目录、禁止执行外部后处理命令/用户配置，且对子进程网络做出口控制。不能只检查用户原 URL，然后放任工具跟随任意重定向。工具返回的完整信息对象只保留需要的字段，避免把临时媒体地址或多余标识写入日志。

## 4. 分步骤处理规则

### 4.1 解析链接

1. 从完整分享文字提取 URL，但同时保留原分享文字。
2. 展开短链，每一跳都做域名、DNS、IP 和协议校验，最多 5 跳。
3. 记录 `original_url`、最终 URL、视频 BV 标识、显式分 P 参数 `p`、用户分享的起始时间。
4. 不删除影响内容定位的参数。去重时按视频与分 P 区分，不把 `?p=2` 当跟 P1 相同。
5. 只处理这一条用户选择的视频/分 P，不自动抓整个合集、播放列表、评论和作者主页。

### 4.2 确认分 P 与 cid

分 P 编号是展示顺序；`cid` 才是具体播放内容的定位标识。依据页面元数据或经过验证的分 P 列表获取两者对应关系。

研发时可参考当前工具使用的 `/x/player/pagelist` 分 P 查询和页面信息提取；所有这些站点内部接口都封装在适配器内，不暴露为本项目的稳定 API。读取失败时不凭经验构造 cid。

显式 p 越界返回 `VIDEO_PART_NOT_FOUND`。URL 没带 p 且页面有多 P 时，首版按 P1 保存，但笔记与界面明确“该链接未指定分 P，保存 P1”，允许用户修改；不能声称知道手机里正在播放哪一 P。

### 4.3 发现字幕轨

研发时重点验证当前播放器信息路径 `/x/player/wbi/v2` 的响应；从锁定版本与实际响应确定参数和字段，不把这个路径当永久可用接口。请求只使用当前条目的 BV/aid 和 cid。

结果转换为内部契约：

```json
{
  "video_id": "demo-bv",
  "part": 2,
  "cid": "demo-cid",
  "discovery_status": "available",
  "requires_login": false,
  "tracks": [
    {
      "track_id": "track-demo",
      "language": "zh-CN",
      "label": "中文",
      "is_auto_generated": null,
      "is_translation": null,
      "kind": "caption",
      "download_url": "https://example.com/subtitle/demo.json"
    }
  ]
}
```

ID 统一当字符串处理，避免大整数在 JavaScript 中精度丢失。临时下载 URL 只用于本次下载，不作为永久材料地址。

`discovery_status` 至少区分：`available`、`login_required`、`no_track`、`blocked`、`network_error`、`unsupported`。请求失败、验证页或 JSON 解析失败不能归类为 `no_track`。

2026-09-07 腾讯云服务器匿名实测补充：view 接口 `data.subtitle.list` 匿名可见（轨道 id、语言、ai_type），但条目 `subtitle_url` 为空；player/v2（含 WBI 签名路径）匿名一律返回空列表（热门/知识区/相关视频 80+ 样本无一例外）。即匿名可判断"是否存在字幕轨"，但取不到字幕内容。实现按此区分：player 无轨而 view 列出轨道 → `login_required`（明确提示需要登录/补充字幕文件）；两者皆空 → `no_track`。对有轨视频不得声称"无字幕"（A18）。

### 4.4 选择轨道

- 先排除 `kind=danmaku` 和工具结果中的 `danmaku`；只有非空 caption 列表才算可用字幕。
- 按用户语言偏好选择，默认优先中文；同语言有可靠来源类型信息时优先人工轨，否则保留未知类型。
- 自动生成/翻译标识依据明确元数据或经过验证的适配器映射，不能仅凭“语句流畅”猜类型。
- 不假定工具一定把平台自动字幕放进 `automatic_captions`；检查锁定版本实际结构。
- 保留所选 track ID、语言、类型、获取时间；可用轨清单的非秘密元数据一起保存。默认只下载所选轨，避免不必要请求。
- 有字幕轨但不是偏好语言时，允许用原语言字幕进行中文总结，并标明来源语言；不自动把翻译结果当原字幕。

### 4.5 下载原始字幕

字幕 URL 若是 `//host/path`，补成 HTTPS 后仍要校验目的地。下载时限制 MIME、响应大小、重定向和超时，按字节保存原始响应及 SHA-256。

如果地址已过期，允许重新探测一次同一视频/分 P 的字幕清单，再下载新地址。不能循环反复请求，也不能把下载到的登录页面作为 `.json` 成功保存。

只收到 SRT 的第三方工具结果时，将它标注为 `tool_exported_srt`；未取得平台原始 JSON 就不要生成一个看似原始的 JSON。保留原始 JSON 是生产 HTTP 路径的目标，兼容导入 SRT/VTT 是必须可用的降级路径。

### 4.6 规范化

平台 JSON 若包含 `body[].from/to/content`，将时间转换成整数毫秒，保留原始数值。统一结构为：

```json
{
  "segment_id": "s0042",
  "start_ms": 125400,
  "end_ms": 129800,
  "text": "这里是对应的字幕文本。",
  "source": "platform_subtitle",
  "original_record_index": 41
}
```

检测负时间、结束早于开始、明显超过视频时长、空正文和结构变化；异常进入 warnings 或 needs_input，原始文件保留不变。字幕允许存在重叠或重复说话，不能简单按相同文字全局去重。

输出三份材料：原始文件、标准 SRT/VTT、带 `^s0042` 等块 ID 的 `normalized.md`。正文按时间或语义段合并时，建立合并段与原始记录的映射，不能丢定位。

只拿到字幕中一小段时标注 `partial_text`，不标整片覆盖。字幕结束时间短于影片不一定说明丢失，片尾无对白很常见；应结合轨道记录、平台响应和异常信号判断。

## 5. 登录与失败后的产品行为

首版默认匿名服务器探测，不集中托管 B 站登录 Cookie，不使用运营者账号替所有朋友抓取。模型 BYOK 与 B 站登录态是两套凭据，不能混成一个设置。

遇到 `login_required`：保留视频链接、标题、分 P 和用户备注；显示“需要补充字幕”。用户可以在自己的正常登录浏览器中获取其可访问的字幕文本/文件，再上传本系统；上传字幕文件不等于上传浏览器 Cookie。

如果实际常看视频多数都需要登录，这会明显降低手机纯链接自动化率。此时必须如实给出测试结果，再选择后续增加浏览器字幕导出助手或独立的用户授权会话方案；不能拿匿名测试失败的适配器声称已经实现全自动字幕收藏。用户授权会话方案也不应作为本轮默认新增开发范围。

只有画面字幕或无字幕轨时，同样保留待补充条目，提供“粘贴摘录”“上传 SRT/VTT/字幕 JSON”。**不偷偷启动 ASR，不下载音频，不用视频标题生成假全文。**

2026-09-07 用户登录态实测补充（本机网络，两个样本视频）：

- 带登录态（Cookie 含 SESSDATA）调用 `/x/player/v2`：AI 中文字幕轨（lan=ai-zh）返回可用 `subtitle_url`，直接下载得到标准 `body[].from/to/content` JSON（52 条与 2053 条两个样本均成功）。即**登录态下全自动字幕获取链路成立**，覆盖大多数有 AI 字幕的视频。
- **最小凭据：仅 `SESSDATA` 一个字段即可**，且效果优于整串 Cookie——完整 Cookie（含 buvid3/bili_ticket 等全部字段）反而使 player 返回多语言翻译轨清单且 URL 全空，仅 SESSDATA 则返回 1 条可下载的 AI 轨。
- 人工/翻译投稿 CC 轨（如多语言轨）即使在登录态下 URL 也为空，暂无获取路径；匿名行为不变（见 §4.3 实测注记）。
- 若产品化登录态：应作为每用户可选的加密托管凭据（与模型 Key 同级、独立开关、可撤销），不共享、不落日志；此为新增开发范围，须单独决策。

2026-09-07 决策与实现：用户确认采用按用户托管方案（字幕文件上传路径保留为无登录态时的降级）。实现为 `ProviderProfile(kind=bilibili_session)` + Credential 信封加密复用，API 为 `GET/PUT/DELETE /v1/bilibili-session`；PUT 只提取并保存 SESSDATA 值（完整 Cookie 输入亦接受但丢弃其余字段），更新后该用户 needs_input 条目自动重新提取；worker 在 login_required 时以最小凭据 Cookie 重试 player/下载，凭据失效（-101）明确提示更新而非冒充匿名失败。

### 2026-09-09 复测：仅 SESSDATA 请求 player/v2 会拿到**别的视频**的字幕

线上现象：不因登录态卡住，但取到的正文要么只有标题，要么完全是另一个视频的字幕。生产环境 4 个视频 × 2 轮实测（extractor 2.0.0 诊断）：

| 请求方式 | 字幕归属正确率 |
| --- | --- |
| `SESSDATA` → `/x/player/v2` | **0/8**——返回的 `ai_subtitle` 地址属于无关视频 |
| `SESSDATA` → `/x/player/wbi/v2`（带 `wts`/`w_rid` 签名） | 4/8 |
| `SESSDATA` + `buvid3` → `/x/player/wbi/v2` | **8/8 正确** |

结论与实现（extractor `bilibili_subtitles-2.0.0`）：

- 登录态一律走 WBI 路径 `/x/player/wbi/v2`，按 B 站规则取 `img_key`/`sub_key` 拼 `mixin key`、加 `wts` 与 `w_rid` 签名；签名失败时**不得**退回普通路径冒充可用结果，如实标 `unconfirmed`。
- 必须携带 `buvid3` 设备指纹（首次向 `api.bilibili.com/x/frontend/finger/spi` 换取并复用），否则同一账号的并发/连续请求会被下发串号的字幕地址。
- 只带 SESSDATA 的旧链路产出的地址**并非报错，而是静默错误**——这是本类问题最难发现的地方，因此下载后必须校验归属：AI 轨地址需包含本分 P 的 cid、字幕时长覆盖需与视频时长匹配；不通过则换轨并重新探测一次，仍不通过进入补充材料，绝不发布错误正文。
- 用户把视频标题粘进正文框（或分享文案里只有标题+链接）时，不再把标题当正文，改走字幕路径。

同一批修复的另一个问题见 docs/08 §6.1：摘录 `claim_id` 的校验规则未写进提示词，导致每条加工都在 enrich 阶段失败。

## 6. 开发者验证命令

以下是供实施人员使用的探测命令，本次没有执行，也不表示已测试成功。先安装并锁定选定 yt-dlp 版本；URL 和语言代码必须替换为实际样本与探测结果。

```powershell
$videoUrl = 'https://www.bilibili.com/video/实际BV号/?p=2'
python -m yt_dlp --ignore-config --skip-download --no-playlist --ignore-no-formats-error --list-subs -- $videoUrl
```

确认列出真正的字幕轨后，再用实际的语言代码导出：

```powershell
$subtitleLanguage = '实际列出的语言代码'
python -m yt_dlp --ignore-config --skip-download --no-playlist --ignore-no-formats-error --write-subs --write-auto-subs --sub-langs $subtitleLanguage --sub-format 'srt/best' --paths '.\subtitle-probe' --output '%(id)s.%(ext)s' -- $videoUrl
```

同时开启两类字幕参数是为了覆盖适配器差异，最终仍以已验证的所选轨为准。`--skip-download` 用于避免下载视频文件；`--no-playlist` 不能代替对分 P/cid 的业务核对。生产调用使用参数数组，不拼 shell 字符串，不接受用户传入额外 yt-dlp 参数。

## 7. 上线前必须完成的样本矩阵

用用户日常实际内容选 10–20 条，不批量扫描平台；在本地网络和目标腾讯云服务器各测一遍。记录日期、提取器版本、匿名访问状态、错误码、字幕数量、语言、分 P/cid、是否产出正确文件。

| 样本 | 必须验证 |
| --- | --- |
| 单 P 人工字幕 | 能取得正确字幕，保留原始文件和时间 |
| 单 P 自动字幕 | 正确标注类型或未知，不误认人工 |
| 多 P 的 P2/P3 | 不得拿成 P1 字幕 |
| b23.tv 分享短链 | 正确展开并保留实际定位 |
| 无独立字幕但画面有文字 | 返回需要补充，不调用 ASR |
| 只得到 danmaku | 判定无字幕，不生成视频全文摘要 |
| 登录后可用、匿名不可用 | 正确标为需要登录；不声称字幕不存在 |
| 平台拒绝或临时网络失败 | 与无字幕区分，有限退避 |
| 字幕地址过期 | 重新探测一次，失败后保留待处理 |
| 用户上传 SRT/VTT/字幕 JSON | 无平台访问也能完成后续 AI 与入库 |
| 同 URL 重试与不同分 P | 重试不重复创建；不同分 P 不误合并 |
| 超长、异常时间或非字幕 JSON | 不崩溃、不写出伪造文字稿 |

匿名自动提取率单独报告，例如 `成功取得有效字幕的条数 / 全部测试视频数`；另报“确认有独立轨的样本”成功率。所有失败均应有待补充记录，但“成功创建待补充记录”不计为字幕提取成功。

若首轮样本显示大部分内容可匿名取到字幕，即可按首版主路径上线；否则应明确保留降级使用体验，再决定是否增加登录态相关工作。
