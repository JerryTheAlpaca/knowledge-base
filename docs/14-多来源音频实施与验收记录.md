## 4. 关键行为与设计决定

- **来源不是 ASR**：`platform/media_kind` 写进 SourceRevision 并随发布继承；`extractor` 记实际适配器（`bilibili_audio` / `direct_audio` / `web_audio` / `audio_upload`），模型信息仍只在 `asr` 元数据里。"机器转写"仅作为处理标记显示。
- **`source_hint=web_inbox` 是采集渠道**，改存 `capture_channel`；最终来源由服务端按真实输入判定（`_capture_platform`），客户端 hint 不能把上传录音伪装成 B 站。
- **输入冻结**：`AsrRun.input_json` 只存来源稳定定位与对象引用（`bilibili:<bvid>:P<n>:cid<cid>:a<id>:b<bw>` / `web-page:<page>#<candidate_id>` / `web-direct:<host>:<hash>` / `upload:<sha256>`），不存请求头与带时效签名的 URL。
- **更换媒体即失效**：`selection` 变化时同一 run 复位检查点，不继续旧的部分结果；来源补充材料使 revision 变化后旧结果作废（沿用原逻辑）。
- **上传即转写请求**：`transcribe_audio` 意图不需要打开 B 站"无字幕自动转写"开关；部署开关关闭时仍保留原件，prepare 显示"等待启用"。
- **大文件不随 Bundle**：原件登记为 `original_audio` 角色，Bundle 只投递文字稿、`asr_raw.json`、`asr_manifest.json`、`transcript.srt` 与 `asr/original_audio.json`（引用说明 + 下载入口）。
- **磁盘控制**：会话创建前检查 `total_bytes + 2GiB` 可用空间；对象输入由 FFmpeg 直接读已落盘对象（可 seek，兼容 moov 在尾部的 M4A），staging 完成时同卷 `os.replace` 收纳，不复制整份原件。
- **失败语义**：网络错误按 `network_error` 有限退避；`audio_too_long`/`audio_stream_unsupported`/`audio_source_unsupported` 等终态进补充材料；网页多候选时 run 停在 `paused/selection_required` 等用户选择，不自动重试。

## 5. 未验证 / 未做的（如实列出）

1. **真实 10 小时音频未跑过**：没有构造/取得 10 小时真实音频，也未在服务器上实测 1800 段的准备耗时、磁盘峰值与内存峰值。按 16kHz/mono/s16 计算，10 小时 PCM 为 1,152,000,000 字节（约 1.073GiB），含原件（最大 8GiB）时单条新增磁盘占用约 11GiB（若实现保留两份上传副本则约 19GiB）——**这是算术估算，不是实测值**。
2. **真实语音未过真实模型**：本次全部识别用假引擎，未用 `sense_voice` 跑真实语音；未新增真实模型质量/耗时数据（沿用 docs/12 的历史结论）。
3. **真实来源样本缺失**：没有真实的"网页静态音频"页面与"音频直链"样本，也没有真实会议录音；这三类只做了桩测试与解析单测。
4. **B 站真实样本矩阵**（docs/07 §1.3 遗留）仍未完成；本次只保证现有 B 站路径未回归。
5. **部署本身已做，但线上功能未真机走查**：push 后 `kb-auto-deploy` 已自动完成构建、迁移与重启（`DEPLOY OK: 59f5758`，`/health/ready` 全 true，`audio_assets`/`audio_upload_sessions` 在库、`asr_runs` 三列就位、`POST /v1/audio-uploads` 未带凭据返回 401 说明路由已生效）。但**没有**用真实录音在线上跑一次上传→转写→投递的端到端走查。
6. **插件侧未改**：Obsidian 插件未新增 `kb_source_platform`/`media_kind` 与原件引用说明的渲染（docs/13 §5 第 6 条要求"插件按派生 source_type 写入并保留 platform/media_kind"）——服务端字段已就绪，插件侧待做。
7. **未做**：浏览器录音、HLS/DASH 播放清单、DRM、说话人分离、声纹、人名识别、直播常驻采集（docs/13 §1 明确不承诺）。
