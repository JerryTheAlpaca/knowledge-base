## 1. 问题清单

### 1.1 视觉质感

#### A. 色彩

| # | 级别 | 问题 |
|---|------|------|
| A1 | 🟠 | **无品牌气质**。`--accent:#2563eb` 是通用 Tailwind 蓝，配冷灰底 `#f5f6f8` + 纯白卡 + `#e3e6ea` 边框，整体是"默认 admin 模板"观感。产品定位是"个人知识收件箱"，气质应偏 calm / editorial（对照：claude.ai 的暖纸底 + 陶土橙，一眼可辨）。 |
| A2 | 🟠 | **层次只靠 1px 边框**。卡片与底色反差弱（白 on 浅灰），无阴影、无底色梯度，页面平面化、"灰蒙蒙"。 |
| A3 | 🟠 | **状态色语义过密且进行态无区分**。9 种 badge 类；`queued / extracting / enriching` 三态共用同一灰色（inbox.html:57）——"静止排队"与"正在加工"看起来一样，用户无法一眼判断系统是否在干活。 |
| A4 | 🟠 | **长 URL 蓝色链接是列表最强视觉元素**。列表把完整原始链接用 accent 蓝 + `word-break:break-all` 全文显示（inbox.html:398），一行行蓝色 URL 淹没了真正重要的状态与平台信息。 |
| A5 | 🟡 | **hover 反馈弱且不一致**。次按钮 hover 变蓝字蓝框（强）、主按钮 hover 仅 `opacity:.92`（弱）、危险按钮 hover 红底；全站无 active 按压态。 |
| A6 | 🟡 | **灰色 badge 对比度不足**。`#6b7684` on `#f5f6f8` ≈ 4.2:1，未达 WCAG AA 的 4.5:1，小字号下发虚。 |
| A7 | 🟡 | **无深色模式**。`:root` 变量已集中，补一套 dark token 成本很低但没做；Obsidian 插件用户相当比例用深色主题，晚间使用网页版刺眼。 |

#### B. 排版

| # | 级别 | 问题 |
|---|------|------|
| B1 | 🟠 | **标题层级失效**。h1=17px / h2=16px / 正文=15px，1px 级差，全靠 600 字重区分，视觉上三级几乎等重，页面"平"。claude.ai 的做法是 serif 展示字 + 明显字阶差，层级一眼可辨。 |
| B2 | 🟠 | **无字阶体系**。12/13/14/15/16/17 六档并存且语义混乱（badge 12、muted 13、kv/按钮 14、正文 15、h2 16、h1 17），没有从 4px 基数或模块化比例推导。 |
| B3 | 🟡 | **placeholder 滥用为帮助文本**。采集链接框的 placeholder 是 40+ 字带分号的完整教学句（inbox.html:110），灰字低对比、输入即消失、屏幕阅读器也不可靠。 |
| B4 | 🟡 | **元信息纯文本拼接，扫读困难**。`r2 · bundle r3 · 创建于 2026/9/9 10:00`（inbox.html:404）无等宽数字、无视觉节奏，版本号与时间糊在一起。 |
| B5 | 🟡 | **行高单一 1.55**。标题、正文、表格、按钮同一行高；长 URL 折行后行间粘连。 |
| B6 | 🟡 | **登录页无品牌表达**。产品名、价值说明、行动按钮三级文案没有做排版区分，首屏像一张表单而非产品门面。 |

#### C. 间距与布局

| # | 级别 | 问题 |
|---|------|------|
| C1 | 🟠 | **双宽度体系，页面失锚**。header 全宽（`padding:10px 18px`）而 main 是 860px 居中列；宽屏下顶栏内容贴视口边缘、正文居中，左右不对齐，视觉重心散。 |
| C2 | 🟡 | **tab 隐喻弱**。`nav.tabs` 是浮在 header 与 main 之间的两个按钮，active 态是圆角色块而非"与内容面板相连"的页签，没有分隔线或面板边界，用户感知不到这是两个"页面"。 |
| C3 | 🟡 | **无间距 token**。3/4/6/8/10/12/14/16/18/20/60px 全都出现，没有 4px 基数系统，间距靠手感。 |
| C4 | 🟡 | **表单节奏混乱**。`label{margin:10px 0 4px}` 全局生效：组内 4px / 组间 10px 对比不足，采集表单四个字段等距堆叠、无主次分组。 |
| C5 | 🟠 | **密度偏高、无呼吸感**。卡片 `padding:14-16px`、卡间距 14px，整页偏"满"。对照 claude.ai 卡片 padding 24-32px、区块间距 24px+ 的低密度。 |
| C6 | 🟠 | **响应式只有一个断点**。仅 `.grid2` 有 640px 媒体查询；header 窄屏换行挤压，模型配置表（4 列、操作列 3 个按钮）在手机上必横向挤压溢出。 |

#### D. 层次

| # | 级别 | 问题 |
|---|------|------|
| D1 | 🟠 | **详情态无导航层级**。`openDetail` 把详情卡插在列表尾部 `#detailHost`（inbox.html:148/420），样式与普通卡片完全一致，仅一个"收起"按钮——没有返回箭头、没有标题栏、没有视觉强调，用户难以感知"我进入了二级视图"。 |
| D2 | 🟠 | **条目行信息层级错配**。第一行（600 字重）是"badge + 平台名"，真正的内容标识（URL）被降为第二行灰色 meta——状态喧宾夺主，内容反而次要。 |
| D3 | 🟡 | **设置页三卡平铺无组织**。偏好 / 模型配置 / B 站登录态同权重纵向排列，无锚点导航、无分组标题；低频的 B 站登录态与高频的默认模型配置争抢视觉。 |
| D4 | 🟡 | **模型配置表格无层次**。无边框、无 hover、无斑马纹，操作列三个按钮与单元格文字争视觉，行高密度大。 |
| D5 | 🟡 | **收件箱内主次不分**。"新采集卡"与"条目列表卡"等宽同样式并列，作为核心内容的条目流没有视觉优先级。 |

#### E. 动效

| # | 级别 | 问题 |
|---|------|------|
| E1 | 🟠 | **全站零过渡**。无任何 `transition` 定义，hover 颜色瞬时切换，所有显隐（tab 切换、详情展开）都是硬切。 |
| E2 | 🟠 | **无加载骨架**。列表、详情、设置全靠"加载中…"文本或静止旧内容；claude.ai 用 shimmer 骨架传达"内容正在来"，等待感完全不同。 |
| E3 | 🟠 | **轮询整表重建**。30s `setInterval` → `loadItems(true)` → `innerHTML` 全量重绘（inbox.html:639/385），无 diff、无入场动画，用户会看到列表闪烁/跳动。 |
| E4 | 🟠 | **加工中无"活"的视觉**。badge 静止，无脉冲/进度指示；一条加工几十秒到几分钟，用户感知不到任何推进。 |
| E5 | 🟡 | **消息瞬现且永不消失**。`.error/.okmsg` 直接 innerHTML 注入，无入场动效、无自动消隐、无 toast。 |

### 1.2 交互逻辑

#### F. 信息架构

| # | 级别 | 问题 |
|---|------|------|
| F1 | 🔴 | **30s 轮询重置用户上下文**。`loadItems(true)` 把 `listOffset` 清零并清空列表（inbox.html:384-385）：用户点了"加载更多"翻到第 3 页，自动刷新一到就被弹回前 20 条、滚动位置丢失。这是实际 bug，不只是体验问题。 |
| F2 | 🟠 | **详情无路由态**。详情是 DOM 内嵌展开，刷新页面 / 前进后退 / 复制链接全部丢失详情状态；浏览器返回键不可用（误按直接离开应用）。 |
| F3 | 🟠 | **waiting_key 引导断裂**。列表显示"等待密钥"，但从这里到"模型与账号"tab 配 Key 没有任何链接或引导，路径靠用户自己领悟。同理 failed 状态也没有指向操作的引导。 |
| F4 | 🟠 | **定位能力只有状态过滤**。无搜索、无平台筛选、无排序选项。按设计容量每天 5-10 条，一个月 150-300 条后无法定位任何条目。 |
| F5 | 🟠 | **空状态缺失**。无条目时 `#itemList` 是一片空白，新用户进来不知道第一步做什么；也没有"未配置模型 Key"的 onboarding 引导（而这是加工跑通的前置条件）。 |
| F6 | 🟡 | **设置页无结构化导航**。三个功能区只能滚动发现，无锚点。 |

#### G. 操作流程

| # | 级别 | 问题 |
|---|------|------|
| G1 | 🟠 | **采集表单"问卷化"**。链接 / 文字 / 备注 / 附件四字段平铺，而真实高频路径是"粘一个链接→提交"。应收敛为单一智能输入框（自动识别 URL / 文字，多链接生成 chip 预览），备注与附件收进"更多选项"。 |
| G2 | 🟡 | **成功反馈抛内部 id**。"已接收 2 条采集（条目 3f9a…、b21c…）"（inbox.html:374）——id 对用户无意义、不可点击；部分失败时同样抛 id 列表（inbox.html:370）且无重试入口。 |
| G3 | 🟠 | **详情操作后强制关闭详情**。重新加工 / 重新提取 / 删除都 `closeDetail()` + 整表刷新（inbox.html:454/461/469），用户无法原地看到操作后的状态变化（如 badge 变"排队中"），想确认结果要重新点开。 |
| G4 | 🟠 | **重新提取无说明无确认**。该操作有 10 分钟限频、会产生新 source_revision 的语义，按钮旁无任何解释（对比：删除有 confirm）。needs_input 条目用户最易误点。 |
| G5 | 🟠 | **原生弹窗三件套**。`alert`（测试配置）、`prompt`（换 Key）、`confirm`（删除/撤销）（inbox.html:578-582）——与页面风格割裂、移动端体验差；`prompt` 里粘贴长 API Key 不可视、易错。 |
| G6 | 🟡 | **文件选择无回显**。选了什么文件、多大、能否移除全不显示，选错只能重选覆盖。 |
| G7 | 🟡 | **无快捷键**。Ctrl+Enter 提交采集等高频效率操作缺失。 |
| G8 | 🟡 | **表格内危险操作无视觉区分**。模型配置表里的"撤销 Key"是普通按钮样式（inbox.html:539），与"测试"同外观；B 站卡的"撤销"反而是 danger 样式，不一致。 |

#### H. 状态反馈

| # | 级别 | 问题 |
|---|------|------|
| H1 | 🟠 | **进行中状态无推进感知**。queued→extracting→enriching 只变文字 badge，无流水线视图、无进度、无"正在动"的视觉；详情页打开后也是静态快照，条目加工完成不会自动更新详情。 |
| H2 | 🟠 | **失败状态无行动引导**。failed 只显示一行 `state_detail` 文本，没有一个与之视觉关联的"重试"主按钮（"重新加工"按钮存在，但和失败状态没有关联表达）。 |
| H3 | 🔴 | **401 丢表单上下文**。`api()` 遇 401 直接 `showLogin()`（inbox.html:240），用户填到一半的采集内容全部丢失；中心登录回跳后页面整体重载，从零开始。 |
| H4 | 🟡 | **消息体系混乱**。`capMsg/supMsg/settingsMsg/pfMsg/biliMsg` 五个消息容器各自为政；成功消息永久挂在表单下方不会消隐，多次操作后新旧消息语义模糊。 |
| H5 | 🟡 | **biliCheck 状态映射有冗余 bug**：`r.status === "valid" ? "okmsg" : (r.status === "network_error" ? "error" : "error")`（inbox.html:599）——三元两分支同值，`blocked/invalid/network_error` 语义没有区分，全部显示红色错误块。 |
| H6 | 🟡 | **历史包袱外露**。`STATE_LABELS` 里 `waiting_budget: "等待预算（已下线）"`（inbox.html:284）——已下线概念直接暴露给用户。 |
| H7 | 🟡 | **网络层错误与业务错误不区分**。断网（fetch 抛 TypeError）与 4xx/5xx 走同一 catch，提示语无差别，用户不知道是该重试还是该改输入。 |

## 3. 设计令牌提案（对齐 claude.ai 气质）

### 3.1 色板（light，深色为二期）

| 令牌 | 值 | 用途 | 对照现状 |
|------|-----|------|----------|
| `--bg` | `#FAF9F5` 暖纸白 | 页面底 | `#f5f6f8` 冷灰 → 暖化 |
| `--surface` | `#FFFFFF` | 卡片 | 不变 |
| `--border` | `#E8E6DC` 暖灰 | 分隔线/卡片边 | `#e3e6ea` → 暖化 |
| `--text` | `#1F1E1B` 暖黑 | 正文 | `#1c2430` → 暖化 |
| `--text-2` | `#73726C` | 次级文字 | `#6b7684` → 提对比至 ≥4.5:1 |
| `--accent` | `#D97757` 陶土橙 | 主行动/链接/激活态 | `#2563eb` → 品牌色 |
| `--accent-hover` | `#C96342` | hover 加深（替代 opacity） | — |
| `--accent-soft` | `#F9EAE2` | 激活底色 | `#eaf1fe` |
| `--ok / --ok-soft` | `#3F7E5B / #E7F2EB` | 成功 | 暖化 |
| `--warn / --warn-soft` | `#B26A1B / #FAF0E1` | 待补充 | 暖化 |
| `--bad / --bad-soft` | `#B3402F / #FBE9E6` | 失败/危险 | 暖化 |
| `--info / --info-soft` | `#5570A8 / #EBF0F8` | 等待密钥 | 降饱和 |

状态 badge 统一"图标 + 文字"双通道（不再只靠颜色）；进行态（extracting/enriching）badge 左侧加脉冲圆点。

### 3.2 字阶

| 令牌 | 规格 | 用途 |
|------|------|------|
| `--font-display` | `"Source Han Serif SC","Noto Serif SC",serif` | 产品名、页面大标题、空态引导语（serif 展示字，claude.ai 气质的关键来源） |
| `--font-body` | system-ui 栈（现状保留） | 正文与 UI |
| display | 22px/600 serif | h1/空态标题 |
| title | 17px/600 | 卡片标题、条目主行 |
| body | 15px/1.6 | 正文（行高微升） |
| small | 13px/1.5 | 辅助信息 |
| micro | 12px/1.4 | badge、时间戳 |
| 数字 | `font-variant-numeric: tabular-nums` | 版本号、时间、文件大小 |

### 3.3 间距 / 圆角 / 阴影 / 动效

- **间距**：4px 基数 → `4 / 8 / 12 / 16 / 24 / 32 / 48`，禁用其他值；卡片 padding 升至 20-24px，卡间距 20-24px。
- **圆角**：按钮/输入 8px，卡片 14px，chip/badge 999px。
- **阴影**：卡片 `0 1px 2px rgba(31,30,27,.05)`，浮层 `0 4px 16px rgba(31,30,27,.08)`——轻量单层，不用多重投影。
- **动效**：`--ease: cubic-bezier(.2,.7,.3,1)`；颜色过渡 150ms，位移/显隐 200ms；列表项入场 fade+translateY(4px) 依次 20ms 错峰；骨架屏 shimmer 1.2s 循环。全站 `prefers-reduced-motion` 降级为无动画。

## 4. 各模块改进建议

### 4.1 全局骨架（header + tabs）——解决 C1、C2、B6

- header 与 main 同宽（860px → 建议收窄至 **760px**，内容型单列更易读）居中；左侧 serif 产品名「知识收件箱」，右侧用户 chip + 设置入口 + 退出（收进用户菜单）。
- tabs 改为**下划线页签**（active 底部 2px accent 线 + 文字 accent 色），与内容列左边线对齐；tab 条与内容之间加 1px `--border` 分隔，建立"页签—面板"隐喻。
- 登录首屏：serif 大标题 + 一句价值说明 + 主按钮垂直居中布局，作为产品门面。

### 4.2 采集模块——解决 G1、G2、G6、G7、F3、F5、B3

- **单一智能输入框**（auto-resize textarea）取代四字段平铺：粘贴内容自动识别——纯链接直接入队、文字作为正文、多链接实时解析成 chip 列表（每 chip 显示域名 + ×移除）。"备注 / 附件"收进输入框下方的「更多选项」折叠条。
- placeholder 只留 `粘贴链接、正文或分享内容…`；教学文案移到框下常驻 small 帮助行。
- **Ctrl+Enter 提交**；提交中按钮变 spinner + 禁点；成功后输入框收缩回 idle，弹 toast「已接收 N 条，后台开始加工」带「查看」动作（点击滚动到列表顶部新条目）。
- 文件选择 chip 化回显：文件名 + 大小 + ×移除，可多选累积。
- 无可用模型配置时，输入框上方显示 inline 引导条：⚠ 还未配置模型 Key，条目会停在"等待密钥" → [去配置]（跳设置 tab 并高亮目标卡）。

### 4.3 条目列表——解决 A3、A4、D2、E2-E4、F1、F4、F5、H1、H2

行结构重排（内容优先，状态降级为辅助）：

```
┌──────────────────────────────────────────────┐
│ 【主行·title】 内容标识（标题或 域名+短路径）      09-09 10:24 │
│ 【辅行】 ●已整理 · B站 · 缺封面        r3 · bundle r2 │
└──────────────────────────────────────────────┘
```

- URL 只显示 `域名 + 截断路径`（如 `bilibili.com/video/BV1xG…`），深色正文色而非 accent 蓝，全文放 `title` 悬浮；后续清单 API 若附带标题，主行直接换真实标题。
- 进行态 badge 左侧加**脉冲圆点**（queued 灰点静止、extracting/enriching accent 色呼吸），静止态与活动态一眼可分。
- 失败条目：行右侧直接出现 small 尺寸的「重试」按钮 + 状态文案变 `--bad`，状态与行动视觉关联。
- **加载**：首屏 3 行骨架（shimmer）；**空态**：serif 引导语「收件箱还是空的」+ 一句说明 + 「去采集第一条」按钮（滚动聚焦输入框）。
- **增量刷新取代整表重建**：30s 轮询改为只拉 `limit=已加载条数` 后按 `item_id` diff，仅更新变化行的 badge/时间，不重建 DOM、不动 `listOffset`、不动滚动位置；新条目从顶部 fade-in 插入。修复 F1。
- 列表工具行：搜索框（匹配 URL/平台/state_detail）+ 平台 chip 筛选组 + 状态下拉，"刷新"按钮加旋转 icon 反馈。

### 4.4 详情——解决 D1、F2、G3、G4、H1、H2

- **明确的二级视图**：详情渲染为独立面板（替换列表区或抽屉式滑出），顶部固定条：`← 返回列表` + 内容标识 + 状态 badge；支持 `?item=<id>` URL 参数，刷新/前进后退/分享不丢状态。
- **流水线 stepper**：`提取 → 加工 → 发布` 三段可视化——完成段 ✓ 实点、进行段脉冲半环、未到达段空圈；当前段下方显示 `state_detail`。H1 的核心解法。
- **主按钮随状态变化**：failed → 「重试加工」（primary）、needs_input → 「去补充」（primary 并自动展开补充区）、ready → 「导出」（primary）；其余操作收进次级按钮组。「重新提取来源」按钮下方加 small 说明「10 分钟内限一次，会生成新来源版本」。
- 所有操作**原地刷新详情 + toast**，不再 `closeDetail`；删除走自定义确认弹窗（说明影响范围：服务器材料 vs 本地笔记）后才离开。
- 补充材料、导出文件列表从裸 `<details>` 升级为分区卡；导出列表加文件类型 icon。

### 4.5 设置页——解决 D3、D4、G5、G8、H5、H6

- 左侧（移动端为顶部横向滚动）**锚点导航**：偏好 / 模型配置 / B 站登录态；滚动时当前锚点高亮。
- 模型配置由表格改为**卡片列表**：每配置一卡（kind badge + 模型名 title + endpoint 域名 small + 状态 badge + 右侧「···」菜单收纳 测试/换 Key/撤销）；「撤销 Key」在菜单内且 danger 色。
- **消灭原生弹窗**：换 Key、新建配置改 modal 表单（密码输入 + 明文切换眼睛 icon）；测试按钮点击后按钮变 spinner，结果行内 toast（成功绿 / 失败红，附 `message`）。
- B 站登录态改为状态大卡：三态（未托管 / 有效 / 已失效）各有图标 + 一句后果说明 + 唯一主操作；检测结果的样式映射修正（H5：valid→ok、network_error→warn、invalid/blocked→bad）。
- 清理 `waiting_budget` 等已下线状态的展示逻辑（H6）：未知状态统一 small 灰色原文展示，不带中文误导标签。

### 4.6 授权页（authorize.html）——解决 I1-I3、B6

- 与收件箱共用同一份令牌文件（`tokens.css` 两页引入），消灭双份 `:root`。
- 加产品标识（serif 名称）与设备/账号信息卡片化展示；「登录此插件」大色块主按钮（44px）；批准成功显示 ✓ 动画 + 「可以回到 Obsidian 了」。

### 4.7 反馈与容错体系——解决 E5、H3、H4、H7、G5

- **Toast 组件**：右上角滑入，成功 3s 自动消隐，错误常驻带关闭钮；取代全部 alert 和五个 msg 容器。
- **自定义 modal 三件套**（确认/输入/信息）替换 confirm/prompt/alert。
- **401 保护**：拦截后先把当前表单内容（采集草稿、设置输入）存入 `sessionStorage`，跳登录；回跳 `/inbox` 后检测并恢复草稿，toast 提示「登录已过期，已为你恢复未提交的内容」。
- **错误分级**：`TypeError`（断网）→ toast「网络似乎断开了」+ 重试按钮；业务错误 → 服务端 message 原文展示。
- 全站按钮补 `:focus-visible` 2px accent 外环；触控目标统一 44px。
