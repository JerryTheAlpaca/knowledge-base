## 1. ContentDocument v3（机器格式，`content.json`）

顶层字段（`format_version` 固定 `"3.0"`）：

| 字段 | 类型 | 谁写 | 规则 |
| --- | --- | --- | --- |
| `format_version` | str | 程序 | 只接受 `"3.0"`；其他值消费者必须停止导入并提示升级 |
| `document_id` | str | 程序 | digest `dig-<item_id>`；knowledge `kn-<slug\|hash>`（沿用现有）；synthesis `syn-<share_run_id>` |
| `kind` | str | 程序 | `digest`\|`knowledge`\|`synthesis` |
| `revision` | int | 程序 | digest/synthesis = 所在 BundleRevision.revision（或分享产物版本），天然不可变；knowledge = 本地主题 revision |
| `created_at` | str | 程序 | ISO-8601 UTC |
| `title` | str | 模型 | ≤200，空则由程序用来源标题 |
| `summary` | str | 模型 | ≤500；`partial` 且摘要受影响时程序置空 |
| `sections` | arr | 模型 | ≤40；元素 `{heading: str(≤200), blocks: [...]}`；heading 同篇内不要求唯一 |
| `blocks[].kind` | str | 模型 | `claim`\|`quote`\|`suggestion`\|`text` |
| `blocks[].text` | str | 模型 | ≤2000；允许必要 Markdown；禁止 Obsidian 路径/内部链接/`^c0001` |
| `blocks[].refs` | arr[str] | 模型给 `R*`，程序转 `e*` | 文档内引用表键，非永久身份 |
| `references` | obj | 程序 | `{"e1": ref, ...}`，见 §2 |
| `limitations` | arr[str] | 模型 | ≤10，每条 ≤1000 |
| `completeness` | obj | 程序 | 见 §4 |
| `provenance` | obj | 程序 | `{"recipe_version": str, "task": "digest"\|"knowledge_fusion"\|"share_synthesis", "input_documents": [{"document_id","kind","revision"}], "source_revisions": [{"item_id","source_revision"}]}` |

硬性边界：单文档 `blocks` 总数 ≤200，`references` ≤60，序列化 UTF-8 ≤512 KiB。**不给 sections/blocks 分配业务 ID**，顺序即数组顺序。不新增数据库表存内容块。

## 2. 引用表：R（任务内）→ 真实原文 → e（文档内）

`ref`（`references` 的值）：

    {
      "item_id": "…",
      "source_revision": 3,
      "segment_ids": ["s0012", "s0013"],
      "source_text_hash": "<sha256 hex>",
      "locator": {"kind": "time", "start_ms": 74000, "end_ms": 82500}
    }

- `segment_ids` 必须属于该 `item_id + source_revision` 的 `segments.json`，且按原文顺序**连续相邻**；不连续依据拆成多个 ref。
- `source_text_hash = sha256("\n".join(该范围内 segment 原文).encode("utf-8"))`，原文取该固定 revision `segments.json` 的 `text`，不做空白归一。写入、下载、迁移同一算法。
- `locator` 可选，只用于界面显示自然位置：`time{start_ms,end_ms}`\|`paragraph{paragraph_id}`\|`line{line_no}`。禁止把 `R1`/`e1`/`s0001` 显示给用户。
- 任务内 `R` 表：`{"R1": {"item_id","source_revision","segment_ids","text","locator"}}`。规则（docs/23 §4.1）：程序按材料顺序统一分配，多来源不会出现两个 `R` 指向同一片段、也不会让两份材料的 `s0001` 互相覆盖；分块与修复沿用同一绑定；每次调用的输入与 R 表固定持久化（新增 `jobs.input_json`，见 §7）。
- `e` 键由程序按引用出现顺序生成（`e1`,`e2`…），固定在该 `document_id + revision` 内，脱离文档身份无意义。
- quote 逐字校验：`normalize_for_quote`（去全部空白）后必须出现在被引 ref 拼接原文中；最多规范化空白，不改文字。

## 3. 模型输出主体与任务扩展

所有生成任务共用主体：`{title, summary, sections[{heading, blocks[{kind, text, refs:["R1"]}]}], limitations[]}`。禁止模型输出 `format_version/document_id/revision/references/provenance/completeness/source_text_hash/任何哈希或 UUID`：模型多返回这些字段时**忽略其值、程序自填、不请求修复**。

- 单篇提炼：只有主体。
- 知识融合：主体 + `no_op: bool`、`change_summary: str(≤1000)`、`conflicts: [{"topic": str, "description": str}]`。`no_op=true` 时主体可缺省，不重发整篇正文。
- 分享整合：主体 + `reader_goal: str(≤500)`、`visualization_intent: str(≤1000)`、`material_usage: [{"ref": "R3", "note": str(≤500)}]`。引用沿用同一套 `R`，不引入第二套 citation 编号语法。

程序组装顺序（`assemble_content_document`，docs/23 §4.3）：解析与类型/体积检查 → refs 去空白精确去重、只接受给定 `R` → 查表得真实范围 → quote 在相邻原文内逐字匹配 → 生成 `e` 键并改写 refs → 写文档身份/来源版本/规则版本/输入记录 → 生成 Markdown 与阅读视图。组装返回 `(document, report)`；`report.errors` 用固定分类码：`json_unparsable`\|`missing_subject`\|`truncated`\|`bad_ref`\|`quote_not_verbatim`\|`empty_document`\|`ref_table_mismatch`\|`limit_exceeded`。

## 4. 完整 / 部分 / 失败

`completeness` 对象（进 `content.json`、manifest、阅读 API 三处，同一份值）：

    {
      "state": "complete",
      "missing_stages": [],
      "gaps": [
        {"code": "quote_not_verbatim", "message": "部分摘录未能核实",
         "refs": ["e3"], "segment_ids": ["s0012"], "block": [1, 2]}
      ],
      "dropped_blocks": 0,
      "repair_calls": 0
    }

| 状态 | 判定 |
| --- | --- |
| `complete` | 所有块校验通过、无失败块、摘要未被清空 |
| `partial` | 有有效内容，但存在被丢弃的块 / 失败块 / 摘要被程序清空；**不得当完整成功发布** |
| `failed` | 无有效主体：JSON 修复后仍不可解析、缺必填主体、截断，或所有 claim 引用无效、只剩空架子 |

`missing_stages` 机器码：`chunk:<n>`\|`summary`\|`quote_verification`\|`evidence_resolution`\|`legacy_evidence_unresolved`。`gaps[].message` 是给用户看的中文文案，界面禁止渲染枚举。

与现有状态体系映射（**不加 DB 枚举、不加迁移**）：

| v3 | `processing_state` | `pipeline_state` | `state_reason` | `cloud_digest.state` |
| --- | --- | --- | --- | --- |
| complete | `ready` | `ready` | `""` | `ready` |
| partial | `ready` | `ready` | `partial_result` | `ready` + `completeness.state="partial"` |
| failed | `failed` | `failed` | 沿用 `model_output_invalid` 等 | `failed` |

新增 `state_reason` 机器码：`partial_result`（部分可用）、`chunk_failed`（块失败，归 partial）、`all_refs_invalid`（归 failed）。`unknown_outcome` 语义不变，不作为自动重发计费的借口。发布与统计口径按 docs/23 §5.3：分别统计完整成功、部分可用、失败、修复调用次数。
