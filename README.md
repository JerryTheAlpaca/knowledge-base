## Obsidian 插件构建与安装（M3）

```bash
cd apps/obsidian-plugin
npm install          # 或使用 npmmirror 源
npm run build        # tsc 类型检查 + esbuild 产出 main.js
```

把 `main.js`、`manifest.json` 复制到 Vault 的 `.obsidian/plugins/knowledge-inbox/` 目录，在 Obsidian 设置中启用第三方插件后开启「Knowledge Inbox」。首次使用：填服务器地址 → 插件设置中点「登录账号」→ 系统浏览器打开授权页，用统一账号确认「登录此插件」→ 插件自动领取设备 Token（存入 Obsidian SecretStorage，旧版本降级存本机数据并提示）。「断开设备」撤销服务端凭据；已导入的笔记不受影响。

已确认条件：电脑关机时也要完成 AI 加工；服务器 2 核 2GB，可升级至 2 核 4GB；每天约 5–10 条，B 站视频通常约 20 分钟。

当前已实现范围仍以已有字幕获取与主体流程为主。2026-09-09 更新 [B 站播放音频流 ASR 实施交接方案](docs/11-B站无字幕视频本地ASR可行性与实施方案.md) v2：主模型为指定 Dolphin INT8，效果不佳再试指定 SenseVoice INT8；直接读取播放音频流，在整套服务约 1GB 限额内空闲时分段识别、繁忙时让出。文档包含执行 Agent 的接口、迁移、配置与验收清单，尚未实施或开启 ASR。

首版设计：iPhone 采集，服务器按用户加密托管各自的模型凭据并调用 API，Obsidian 插件在电脑上线后下载成品与原始材料。每人的 Vault 仍只保存在自己的电脑；服务器仅暂存本系统采集的材料及加工结果。加密托管不是端到端加密：服务器运行时可以使用凭据并读取内容。本文是设计方案，尚未上传任何 Key 或配置实际托管。
