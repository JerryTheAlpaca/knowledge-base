# 个人知识摄入系统

本文档集根据用户提供的《目前方案.md》整理，目标是把公众号、小红书、B 站、网页、AI 对话和个人灵感，可靠地保存并加工到每位用户自己电脑上的 Obsidian。

版本：开发设计草案 v1.2 · 2026-09-07。

- [方案评审与架构决策](docs/01-方案评审与架构决策.md)：现有方案的问题、保留的方向和建议调整。
- [开发设计文档](docs/02-开发设计文档.md)：产品范围、数据结构、接口、同步、AI 加工、插件、部署和迁移规范。
- [开发任务与验收清单](docs/03-开发任务与验收清单.md)：实施顺序、交付物和可执行验收场景。
- [B 站字幕获取专项设计](docs/04-B站字幕获取专项设计.md)：字幕轨探测、分 P/cid、登录限制、原始字幕留存和验证命令。

建议先读方案评审，再按开发设计文档实施。应用代码已按《开发任务与验收清单》的里程碑顺序开始建设：M1「可靠接收」的服务端（FastAPI + Worker + SQLite，含幂等 Capture、对象存储、投递清单与回执）已实现并通过集成测试，位于 `apps/server/`；M2 云端加工、M3 本地入库、M4 主要来源适配仍在开发中。接口契约见 `contracts/openapi.json`。

已确认条件：电脑关机时也要完成 AI 加工；服务器 2 核 2GB，可升级至 2 核 4GB；每天约 5–10 条，B 站视频通常约 20 分钟。

最新范围：首版不做 ASR，集中做好已有字幕获取与主体流程；小米 ASR 以后再评估。

首版设计：iPhone 采集，服务器按用户加密托管各自的模型凭据并调用 API，Obsidian 插件在电脑上线后下载成品与原始材料。每人的 Vault 仍只保存在自己的电脑；服务器仅暂存本系统采集的材料及加工结果。加密托管不是端到端加密：服务器运行时可以使用凭据并读取内容。本文是设计方案，尚未上传任何 Key 或配置实际托管。
